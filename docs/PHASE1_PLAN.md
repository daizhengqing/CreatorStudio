# 第一阶段实施计划（Phase 1）

## 1. 范围确认

**目标**：本机打开浏览器，即可导入/下载视频，整理素材，做基础剪辑并导出 MP4。

**布局**：整个页面只有上下两区：顶部 Toolbar；下方完整自由工作区。工作区窗口包括「素材库」「解析下载列表」「剪辑工作台」「素材详情」「导出队列」，应允许同时打开、拖拽、调整尺寸、叠放、关闭及重开。

**暂不做**：账号系统、云端部署、多人协作、内容发布、热点爬虫、AI 视频、ComfyUI、自动字幕、复杂特效和调色。

## 2. 里程碑

### M0 — 工程骨架与多窗口工作区

- [x] pnpm Monorepo、React、shadcn/ui（Neutral）、Fastify、SQLite、共享类型。
- [x] 顶部 Toolbar，打开 / 关闭窗口。
- [x] react-rnd 窗口拖拽、缩放、置顶、最小化、恢复布局。
- [x] Zustand 本地持久化当前浏览器中的窗口布局。
- [ ] 更稳定的最大化 / 还原、窗口吸附边界、工作区溢出处理。
- [ ] 多尺寸屏幕上的响应式默认布局与保存多套布局预设。

**验收**：刷新浏览器之后，已经打开的窗口和位置不丢失；窗口相互重叠时点击可置顶。

### M1 — 素材库

- [x] 本地媒体文件上传、分类展示、搜索、预览、缩略图初版。
- [x] SQLite 素材元数据；文件存本地目录。
- [ ] 文件去重策略（哈希）、拖入导入、批量处理与导入错误详情。
- [ ] 标签、收藏、排序、目录/集合、文件监听与重新扫描。
- [ ] 大文件直接引用（避免在同一电脑上二次复制）。
- [ ] 缺失文件检测、批量删除、同名文件行为、素材引用保护。

**验收**：能够导入几十个视频/图片/音频，关闭重开后仍可查询、预览。

### M2 — 视频链接下载

- [x] 输入单个 B站 / 抖音 / YouTube HTTPS 链接，后台调用 yt-dlp。
- [x] SQLite 任务记录、队列执行、进度展示、成品入素材库。
- [ ] 解析预览：标题、封面、可选清晰度与下载选项。
- [ ] 失败重试、取消、可靠任务恢复、批量粘贴链接。
- [ ] 平台兼容性与登录态处理；敏感 cookies 必须安全存储、不得提交 Git。
- [ ] 下载任务名称/来源元数据补全、日志查看。

**验收**：成功完成下载的合法视频自动出现在素材库；失败要返回可读原因，不能假成功。

### M3 — 基础剪辑器（主要工作量）

- [x] 单视频预览、起止时间参数、静音原声、选择 BGM、选择输出画幅的初版交互。
- [ ] **剪辑项目 JSON 数据模型**（项目与素材分离，源文件不可变）。
- [ ] 多视频片段放入视频轨、拖动顺序和位置、拖动边缘剪裁、播放头与预览同步。
- [ ] 分割/删除片段，时间轴刻度与缩放、吸附、撤销/重做。
- [ ] 从视频中抽离音轨进行独立静音/音量控制，支持多音频片段位置管理。
- [ ] 画幅 16:9 / 9:16 / 1:1、裁切位置和缩放；画面预览和导出效果一致。
- [ ] 项目自动保存和重新打开；缺失媒体处理。

**验收**：把两段视频、一段 BGM 放到时间轴；删除片头、调整顺序、改变画幅；刷新后项目仍完整、可编辑。

### M4 — FFmpeg 导出与任务管理

- [x] 单片段裁剪 + 画幅 + 静音/BGM 合成输出 MP4 的基础端到端实现。
- [x] SQLite 持久化导出任务；导出列表实时进度。
- [ ] 从多轨项目 JSON 编译可靠的 FFmpeg 滤镜图；完整非线性合成。
- [ ] 音画同步、输出分辨率/码率/帧率、封面、编码加速选项。
- [ ] 可取消/重试的导出、异常清理、导出成品重新进入素材库。
- [ ] 磁盘空间检查、任务日志和错误反馈。

**验收**：导出的视频与工作区预览的画幅、片段顺序、音频选项一致，且不会修改原视频。

### M5 — 整体打磨

- [ ] 组件与业务模块拆分，单文件 <= 500 行。
- [ ] 一键启动、首启依赖检测（Node/FFmpeg/yt-dlp）、本地数据目录设置。
- [ ] 多平台下载异常与跨系统本地文件路径手工测试。
- [ ] 任务中断恢复策略、性能和大文件验证。
- [ ] 完整的阶段一人工验收清单。

## 3. 建议开发顺序

先修补 M0、M1 的易用性（预计 1–3 天），再完善 M2（预计 2–4 天），随后集中实现 M3（预计 5–10 天），最后 M4/M5（预计 3–6 天）。这些只是**单人熟悉当前技术栈时的粗估**，取决于视频编解码差异、时间轴组件可用性和兼容性，不能视为承诺排期。

**关键路径**：M3 时间轴交互和「项目 JSON -> FFmpeg 滤镜图」是技术风险最高部分，应在大规模写 UI 之前用 2 视频 + 2 音频的最小样例验证播放器时间、裁剪与成品一致性。

## 4. 建议项目 JSON 形态（尚未实现）

```json
{
  "version": 1,
  "projectId": "project-uuid",
  "canvas": { "width": 1080, "height": 1920, "fps": 30 },
  "tracks": [
    { "id": "video-1", "kind": "video", "clips": [
      { "assetId": "asset-uuid", "position": 0, "sourceStart": 1.5, "sourceEnd": 8.0 }
    ] },
    { "id": "audio-1", "kind": "audio", "clips": [] }
  ]
}
```

这里的 `position` 是片段在项目时间线中的起始秒数，`sourceStart/sourceEnd` 是原素材入点/出点。不得直接把项目 JSON 当作 FFmpeg CLI 参数，必须有验证与编译层。

## 5. Definition of Done

- `pnpm install`、`pnpm dev` 可启动；`pnpm typecheck`、`pnpm build` 通过。
- 任何一个视频不被原地修改，导出文件单独保存。
- 下载失败与导出失败能通过 UI 查看原因。
- 关闭重开工作台不会丢失素材数据或已保存的项目数据。
- 人工验证 Windows/macOS 下至少各一个标准 MP4；检查 9:16 导出、音轨消除、新增 BGM。
